# Debit Note 產生器

一個單一 HTML 檔的小工具，用來取代手動編輯 Debit Note Excel。填表單 → 按「下載 Excel」→ 產生格式化好的 `.xlsx`。

## 怎麼用

1. 直接用瀏覽器打開 `index.html`（雙擊即可，不需要架站、不需要安裝任何東西）。
2. 第一次打開需要連網，才能載入畫表格用的 ExcelJS 元件（之後同一台電腦重複開，只要連過一次網路即可，若一直沒連過網會顯示提示訊息）。
3. 填「單據資訊」「賣方/收款銀行資料」「品項明細」「簽署資訊」。
4. 按右下角「下載 Excel」，會產生一份 `DebitNote_賣方名稱_單號.xlsx`。

## 廠商資料怎麼重複使用

- 「賣方/收款銀行資料」上方有下拉選單，可以把常用的廠商（含銀行帳戶資訊）存起來，下次直接「套用」不用重打。
- 資料存在**你自己瀏覽器**的 local storage，不會跟別人共用、也不會上傳到網路。
- 要分享給同事：按「匯出設定(JSON)」存一個 `debit-note-vendors.json`，傳給對方，對方用「匯入設定(JSON)」載入即可。

### 上傳廠商資訊自動帶入（PDF / 圖片，OCR）

- 「賣方/收款銀行資料」區塊上方可以直接上傳廠商的付款約定書 PDF 或照片，會自動辨識文字帶入欄位。
- **可以一次選多個檔案**（例如中文版＋英文版各一份），會逐份分開辨識、分開解析，再自動合併：辨識結果是中文就填中文欄位（賣方中文名稱/中文地址/開戶行），是英文就填對應的英文欄位（賣方英文名稱/英文地址），兩份檔案不會互相蓋掉。展開「辨識到的原始文字」可以看到每份檔案各自的辨識結果（用「===== 檔案 N：檔名 =====」分隔），手動修正後按「重新套用」也會照這個分隔線分開重新解析。
- **這個功能準確度會隨掃描品質浮動**，帳戶號碼、SWIFT Code 這種關鍵欄位如果辨識結果格式看起來不合理（例如不是純數字），工具會直接跳過不填，不會塞錯資料進去 —— 但其他欄位（賣方名稱、地址、開戶行等）沒有這層防呆，套用後**務必逐一核對**，可以展開「辨識到的原始文字」對照。
- 掃描品質好、字體工整的文件辨識率會高很多；歪斜、模糊、有雜訊的掃描件容易連英文標籤本身都認錯，導致該欄位直接抓不到。

## 品項明細每一列可以做的操作

每一列最右邊有 4 個小按鈕（2x2 排列）：

- **↑ / ↓**：把這一列往上或往下移一格，用來調整品項在單子上的順序。
- **⧉ 複製**：把整列內容（日期/貨號/款式/板式/數量/單價）複製成新的一列，插在原本那列下面，方便改一兩個欄位就好，不用整列重打。
- **✕ 刪除**：刪掉這一列。

## 品項明細怎麼快速帶入

- 「品項明細」表格上方可以直接上傳整理好的 `.xlsx` 或 `.csv` 檔。
- 上傳後**不會馬上蓋掉表格**，會先出現一個確認畫面：自動猜每一欄（日期／貨號／款式／板式／數量／單價）對應到檔案裡的哪一欄，並列出前幾筆預覽。辨識錯了就直接改選下拉選單，預覽會即時更新，覺得沒問題再按「確認匯入」；按「取消」就什麼都不會變。
- 支援繁體、簡體標題（例如「単价／单价」「数量／數量」「类别／款式」都認得）。
- 會自動找到資料的合理範圍：遇到「合計/小計/總計」列或連續空白列就停止，也會在偵測到下一段像是「另一張表」的標題列時停止，避免把後面不相干的表格（例如出貨追蹤表）一起吃進來。
- 這個是讀純文字/表格資料，不是圖片辨識，只要是打字檔案（不是掃描圖），準確度很高。但實際工作表格式五花八門，還是建議送出前看一下確認畫面的預覽再按確認。
- 舊版 `.xls` 檔案要先在 Excel 另存成 `.xlsx` 才能上傳。
- 匯入的中文內容（品項、廠商名稱/地址等）會**自動簡轉繁**，廠商給的資料算簡體也沒關係。

## 交接給同事

- 整個 `debit-note-generator` 資料夾（`index.html` + 這份 README）可以直接複製給同事，或放到公司共用雲端硬碟。
- 不依賴任何個人帳號登入，同事拿到檔案就能直接用。
- 如果之後要加欄位或改版面，直接編輯 `index.html` 裡的 `<script>` 區塊即可，是一般的 HTML/JS，沒有其他建置流程。

## 已知限制

- 品項「日期」欄位是純文字，原單據上是用「6月」這種簡寫，所以工具沒有強制格式，可以直接打「6月」或完整日期都可以。
- 快遞費沒有獨立欄位，做法是在品項明細多新增一列，款式打「快遞費」，數量填 1、單價填金額即可，會自動算進合計金額。
